Privacy

Your history stays yours.

The public Apply Vigil Mac app is local-first and needs no account.

Application data

Your counts, UTC dates, goals, drafts, and alert inbox are stored in the app’s system-managed local WebKit data on your Mac. The public app blocks the legacy owner-tracker API. Its private backup identity grants access only to that identity’s backup versions.

No monitoring or telemetry

The app does not read your browser, LinkedIn account, screen, prompts, or other applications. It includes no analytics SDK. Beta 6 starts with local saving only. Cloud backup starts when you choose to link Google in Settings → Data. Existing backup connections from earlier versions remain supported. Counts are entered manually.

Files you choose

JSON and CSV exports are written using a save dialog to the location you choose. JSON restore reads the file you select and merges missing records locally. Keep backups somewhere you control.

Login and Keychain

The public app requires no account and does not read or write saved owner-session Keychain items. Beta 2 removes the legacy Keychain integration. macOS first-launch approval is a separate system check and can still require authentication.

Optional Mac features

macOS notifications and launch at login are optional. The app requests notification permission when you enable banners. It does not require Accessibility, Automation, Screen Recording, camera, or microphone permission.

This website and downloads

The website is hosted on Cloudflare and release files are hosted on GitHub. Those services receive ordinary web requests when you visit or download. This site has no added analytics scripts, advertising pixels, or account forms. Product demonstrations use synthetic data.

Moving or removing data

Export a JSON backup before removing the app or its local data. Moving the app to Trash does not automatically erase its history or preferences. Cloud backups are separate from the legacy web tracker. They do not automatically merge or overwrite its records.

Google backup and recovery

Google sign-in is optional. We receive your Google account ID and email address to link your private backup and restore access after reinstalling. We do not receive your Google password or request Gmail, Drive, contacts, or calendar access. Google handles sign-in; application history is saved in our Cloudflare database. Each account can access only its own backup. Normal use stays signed in on this Mac, and local saving works offline. You can revoke the device connection in Settings → Data; this stops its access and retains existing cloud copies.

Earlier backup connections and recovery files

Beta 5 generated a random identity and 256-bit access secret automatically; no email, password, hardware serial number, or account registration form is used. The secret is saved in a private Application Support file without Keychain. This is filesystem access protection, not application-level encryption. The server stores its hash. Full-history versions are uploaded over HTTPS, downloaded, and checked before the app reports Backed up. An installation can access only its own backups. Save a recovery file outside the Mac if you want recovery after all app data is deleted. The recovery file contains the access secret: anyone holding it can access that backup. Without that file or the original identity, the service cannot safely identify you from a hardware ID. Turning the connection off revokes the credential and leaves existing cloud copies retained.
